What it's NOT.

This project's whole ethos is honesty, so here is the blunt version. Everything below is drawn from an independent audit and a live pilot test — not marketing copy. If you take one thing away: this is a strong methodology whose execution engine is still being wired.

The independent verdict

58/100 — classified “Prototype Only”

An independent Agentic System Auditor — fresh, adversarial, with no stake in the project — scored the whole system and delivered the verdict unedited. It is deliberately blunt: “disclosure of an absent runtime does not convert it into a present one.”

58/100
0Prototype (55–69)PilotProduction100

The score is deliberately bimodal, and the band reflects the weakest production-critical layer, not an even mediocrity. Governance and validation scored production-ready-grade (8/10 each); tool usage, state, and operational readiness scored 3–4/10 because there is no proven runtime. A system can't outrank its weakest production-critical layer — so the whole classifies as Prototype Only.

LayerScoreWhy
Governance8/10Exceptional versioning, validator, CI, lifecycle

Operational readiness3/10No proven runtime, no isolation, no budgets

The auditor's own summary: the methodology is roughly pilot-ready (~72); the system as a whole, including its unproven runtime and doubled tools, is Prototype Only (58).

Be blunt with me

Seven things this is not

×

NOT production-ready

The independent audit scored it 58/100 and classified it “Prototype Only.” It is fit for continued supervised pilot / internal reference use — not for unattended, customer-facing, or mission-critical work.

True status: supervised pilot / reference build.
×

NOT proven in live execution

Everything was tested against simulators and test doubles — every external service (Vercel, Neon, Clerk, a payment provider, a booking provider) was a mock. Nothing has run against real credentials. The runtime kernel logic is real and tested, but the part that spawns real agents is a documented stub. It needs a credentialed run to prove itself.

True status: kernel logic real; live run not yet demonstrated.
×

NOT for global corporates

It is SME-scoped (tiers T0–T2) by explicit owner decision. Multi-entity structures, nested/federated manifestos, and role-based access for enterprise (T3–T4) are documented as a future path but deliberately not built — building them now would be exactly the over-engineering the audit warns against.

True status: micro to mid-SME only.
×

NOT a no-human autopilot

Human approval gates are mandatory by design. Work blocks on your signature at manifesto sign-off, pre-flight, and release. In the pilot the human gates didn't rubber-stamp — they materially changed the product. If you want fully autonomous agents, this isn't that, on purpose.

True status: human-in-the-loop is a feature, not a gap.
×

NOT a home for your API keys

Bring your own key. The repo ships with none, your keys never leave your device, and they're redacted everywhere beyond the last 4 characters. Nobody can ever use the owner's credentials — the app fails loud and stops if a key is missing rather than falling back to a default.

True status: BYOK, keys stay local.
×

NOT a guarantee of business results

It produces auditable, disciplined delivery — not guaranteed outcomes. In the pilot the headline business metric was un-measurable at day 14 (no analytics wired, no live traffic). The framework is honest that a well-run process is not the same as a proven result.

True status: good process ≠ guaranteed outcome.
×

NOT a finished product

It's a strong methodology with an engine still being wired. The governance and validation layers are genuinely excellent; the runtime, tool-resilience, and real-world integration layers are the acknowledged work in progress. Fund the trajectory — withhold the “production” label until the runtime exists.

True status: methodology strong, engine in progress.

Why we lead with this

The honesty is the feature

Most “agent framework” pitches hide their gaps. This one built an auditor to find them and publishes the score. The framework audits itself — and that self-scrutiny is the strongest signal that its stated roadmap will actually be met.

28 self-caught defects

The pilot's most valuable output was a precise, evidence-backed catalogue of roughly 28 of its own process weaknesses.

3× refused to fabricate

The non-fabrication discipline held at every test point — the AI refused to present invented data three separate times.

2× caught a planted bug

A deliberately disguised seeded defect was caught independently by two different reviewers, from different evidence.

What comes next

The honest roadmap

The gaps above are not a mystery to the project — they are its named next milestones, in order.

  1. Wire the runtime executorConnect the tested kernel to real subagent spawning, so waves fire, timeouts track, and dead agents are detected without a human turning the crank.
  2. Add a tool-resilience layerGive every tool a timeout, retry, fallback, and auth contract — the single most production-critical gap — then prove it against real services in a staging tier.
  3. Productise into the Mimir ConsoleA single-operator dashboard: wave board, decision inbox, RAG/RAID, and a document review-and-approval surface — the human-gate interface, built on BYOK.

Explicitly reserved and not being built: enterprise/global multi-entity support (nested manifestos, role-based access, federated cascade). Named, scoped, and left uncoded — on purpose.
