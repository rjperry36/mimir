Mimir — the Organisational Intelligence Engine.

A governance-first way to run AI delivery teams: interview a business, agree a manifesto, then let specialist AI teams do the work — with a human approving every big decision and the whole system versioning and auditing itself. What it is

One manifesto. Specialist AI teams. A human in charge.

In one sentence: Mimir captures a business's strategy once as a "manifesto" (an Executive Command Layer), then cascades it down to reusable rosters of specialist AI agents that deliver the work under mandatory human sign-off — and it versions and audits every step.

The model in plain English

  1. Interview the business to understand it.
  2. Agree a manifesto — the North Star plus the goals that everything must serve.
  3. Specialist AI teams (rosters) do the actual work — SEO, app development, content.
  4. A human approves the big decisions at fixed gates. Nothing important ships without sign-off.
  5. It learns and versions itself — every change is recorded, nothing changes silently.

Why "governance-first"

Most agent projects start with autonomy and bolt on control later. This one starts with control: a single source of truth, semantic versioning at every layer, a machine-readable registry checked in CI, and human approval gates that are mandatory by design. The independent audit called the governance and validation layers “production-ready-grade” — better than most shipped systems. The execution engine underneath is the part still being built.

How to use it

From your business to delivered work, gate by gate

Step 0 — Bring your own API key (BYOK)

This is not optional and it comes first. The repository ships with no credentials. You supply your own Anthropic/Claude key to run the agents, and your own service keys (Vercel, Neon, Clerk, and so on) per engagement. They stay on your device and are never committed. More on BYOK & security ↓

  1. Run the interviewThe ECL Interview agent conducts a structured business intake and produces a draft manifesto, with an honest gap report of what it doesn't yet know.
  2. Sign off the manifestoYou review, amend, and sign. Work is blocked until you do — in the pilot the owner's edits materially changed the product. The manifesto becomes the single source of truth, versioned v1.0.0.
  3. Pick your tier (T0–T2)The framework is SME-scoped: micro, small, and mid-SME tiers set how deep the manifesto goes, which rosters activate, and how many approvers are needed. (Enterprise/global tiers are documented but deliberately not built.)
  4. Activate a rosterSign the pre-flight record and a roster goes live. It runs work in waves, each with a Goal → Plan → Act → Review → Learn cycle and quality gates.
  5. Approve the gates as work proceedsAt each mandatory gate — pre-flight, release, version bumps — the decision is yours. Nothing important ships without a human signature.

Honest note on execution today

The kernel logic is real and tested, but live agent execution is still human-supervised. In the pilot a person dispatched every wave by hand; the piece that spawns and runs real subagents unattended is a documented stub, not yet proven. Treat this as a supervised methodology you drive, not an autopilot you switch on.

What it achieves

What it actually delivered under test

A real business (Riverside Bookings) was taken through the full lifecycle in a live pilot. Result: 6 PASS / 2 PARTIAL / 0 FAIL against pre-declared success criteria. These are the concrete outcomes — each traceable to a logged event.

Repeatable, auditable delivery

Every decision, gate, and defect is logged and reconstructable. Semantic versioning at every layer; no silent changes. The audit trail let an independent auditor replay the entire run.

A manifesto as single source of truth

One document holds the North Star and goals. Cross-roster work is routed through it and checked against it — agents can't quietly drift from what the business agreed.

Non-fabrication discipline

A blocking rule against inventing data held at every test point: the AI refused to present invented figures 3 times, and a deliberately seeded bug was caught independently by two different reviewers (QA and UX).

Self-improvement via LEARN

Each wave ends by harvesting learnings into version-bump proposals, so the agent definitions improve over time. The pilot surfaced ~28 of its own process defects — arguably its most valuable output.

A real, tested app came out of it

The App Dev roster produced a genuine, building application: 105/105 backend tests, 139/139 frontend, 40/40 database, 53/53 end-to-end, pipeline green, WCAG 2.2 AA met, 0 critical security findings. It was accepted as a verified reference deliverable — not production (every external service was a test double). See what it's NOT for exactly why that distinction matters.

BYOK & security

You bring your own keys. They stay yours.

This framework is meant to be shared publicly, so it is built on a strict bring-your-own-key model — the same approach as most open-source AI tools.

  • The repository ships with no API keys, ever. Only placeholder names in an .env.example are tracked.
  • You enter your own Anthropic key (to run agents) and your own service keys per engagement.
  • Keys are stored client-side / locally only — never committed, never transmitted to any server the project owner controls.
  • Keys are redacted everywhere — not in logs, emitted state, error messages, or the UI beyond the last 4 characters.
  • A CI secret-scan gate stays on and blocks any accidental key commit.
  • If a key is missing the app fails loud and stops — it never falls back to a default or anyone else's key.
